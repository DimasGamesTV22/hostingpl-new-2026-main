## Микросервисные границы

Требование — микросервисы. Реализация — **три независимо разворачиваемых сервиса** с сетевым
контрактом между ними, при этом панель внутренне остаётся модульным монолитом
(модули изолированы сервисным слоем и контрактами, но деплоятся вместе — так дешевле и быстрее,
а при росте нагрузки любой модуль выносится в отдельный сервис без переписывания, см.
`docs/architecture.md#вынос-модуля-в-отдельный-сервис`).

Физические сервисы:

1. **`panel`** — HTTP-приложение. Stateless: сессии в Redis, файлы на S3/CDN, можно реплицировать
   `php artisan queue:work` и `schedule:work` на N инстансов.
2. **`agent`** — по одному на каждую ноду игровых серверов. Держит WSS-соединение с панелью,
   выполняет команды, стримит консоль и метрики. Изолирован от панели: панель не имеет
   SSH-доступа к нодам, всё через протокол.
3. **`bot`** — webhook long-polling к Telegram. Отдельный сервис, общается с `panel` по API.

Горизонтальное масштабирование `panel` возможно сразу: нет локального состояния, сессии и кэш в
Redis, задачи в очереди Redis, файлы на S3-совместимом хранилище.

## Поток операций

### Создание сервера

```
POST /servers
  └─► проверка прав, тарифа, квот, баланса
  └─► транзакция: резервируем порт + ресурсы
  └─► NodeScheduler::pick()  ──► node_id + runtime
  └─► AgentClient::createServer()  (RPC через WSS, ожидание ack)
  └─► agent: создаёт каталог, генерирует конфиг, применяет лимиты, ставит install-скрипт
  └─► агент шлёт события: installing → installing.progress → installed
  └─► panel пишет историю, открывает web-консоль (SSE через панель)
```

### Команда в консоль

```
POST /servers/{id}/console  { command: "say hello" }
  └─► проверка прав (владелец / саб-аккаунт с правом console.write)
  └─► AgentClient::rpc('console.write', ...)  ──► агент ──► stdin процесса
  └─► ответ — мгновенный (ack), stdout приходит отдельным потоком событий
```

### Автопродление / съём

```
schedule:work  (каждую минуту)
  └─► BillingService::chargeDueServers()
       └─► для каждого сервера с expires_at <= now:
            ├── хватит кошелька → списать, продлить
            └── не хватит  → пометить pending, уведомить в Telegram/email
  └─► при 0 балансе дольше grace-периода → stopServer() + снять с публичного мониторинга
```

## Модули панели

Расположены в `panel/app/Modules/<Name>`, каждый экспортирует:

- `Providers/` — сервис-провайдер модуля (маршруты, виджеты, команды, биндинги)
- `Routes/` — HTTP-маршруты модуля
- `Services/` — бизнес-логика
- `Policies/` — правила доступа
- `Http/` — контроллеры, form-request'ы, API-ресурсы
- `Views/` — Blade-шаблоны
- `Console/` — команды artisan и планировщик

Eloquent-модели всех модулей лежат плоско в `panel/app/Models/` (один неймспейс, простой
поиск по проекту). Текущие модули: `Users`, `Games`, `Nodes`, `Servers`, `Billing`, `Payments`,
`Monitoring`, `Backups`, `Support`, `Promo`, `Referral`, `SecretCodes`, `Agent`, `Public`.

## Хранилище данных

| Данные | Где | Почему |
|---|---|---|
| Пользователи, серверы, биллинг | MySQL 8 | Транзакции, FK, отчёты |
| Сессии, кэш, лок-locks, rate-limit | Redis | Скорость, атомарность |
| Очереди (email, install, backup) | Redis | Отдельные очереди с приоритетом |
| Метрики (5-секундные точки) | Redis (кольцевой буфер, TTL 7 дней) | Не раздуваем MySQL |
| Агрегаты метрик (часовые) | MySQL | Графики за 30+ дней |
| Логи и бэкапы игровых серверов | Локальный диск ноды + S3 | Быстро локально, реплика в облако |
| Аватарки, вложения тикетов | S3-совместимое (S3/MinIO/Selectel) | Горизонтальное масштабирование |

Метрики: агент шлёт точками через `metrics.push` батчами раз в 5 секунд. Панель держит
кольцевой буфер в Redis (`gamedock:metrics:{server_id}`) и раз в минуту агрегирует в
`metric_hourly` для долгих графиков.

## Безопасность

- Аутентификация — Laravel Sanctum (сессии) + персональные токены для агента (`agents.token_hash`).
- 2FA (TOTP) обязателен для ролей `superadmin` и `admin` — проверяется в middleware `EnforceTwoFactor`.
- Каждая команда агента подписывается HMAC-SHA256 (`timestamp + nonce + body`), защита от replay.
- Все запросы в панели проходят CSRF; API — `throttle` по токену и IP.
- Файловый менеджер запрещает выход за пределы каталога сервера (realpath-нормализация + whitelist).
- Аудит: `audit_logs` на каждое привилегированное действие, включая чтение чувствительных полей.
